== v0.2 — RS256 sign + verify

*Status: planned.* Zig 0.15 has no public RSA signing path; this is the decision
point.

=== Implementation options

[cols="1,3,3", options="header"]
|===
| Option | Approach | Trade-off

| (a) Hand-rolled | RSASSA-PKCS1-v1_5 on top of `std.crypto.hash.sha2` +
  `std.math.big.int` | ~300 LoC, no dependencies, fully reviewable. Risk: getting
  the PKCS#1 padding right on first attempt (timing-channel risk on padding
  oracle is small for a signing path but real for verification).

| (b) Vendored Zig RSA lib | Pull a known-good RSA implementation (e.g.
  zig-crypto, libsodium-bind) | Fewer LoC to maintain in this repo; introduces an
  upstream dependency that needs vetting + tracking.

| (c) Link OpenSSL / BoringSSL | `@cImport` `openssl/rsa.h` and call `RSA_sign` | Operationally simple;
  defeats the "drop-in `.so`" goal because consumers now need OpenSSL on the
  target. Rejected unless (a) and (b) both fail.
|===

*Leaning: (a).* Padding is fixed-shape (`0x00 0x01 [0xFF...] 0x00 [DigestInfo]`),
the SHA-256 DigestInfo is a known constant byte string, and modular exponentiation
via `std.math.big.int.Managed` is straightforward.
